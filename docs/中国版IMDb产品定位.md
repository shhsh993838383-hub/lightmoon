# 光幕：面向中文用户的全球电影资料与发现平台

更新：2026-10-27

## 产品定位

用户希望打造中国版本的 IMDb。具体定位为：全球电影资料库作为底座，中文语境的细粒度标签与探索工具作为主要选片入口，逐步加入评分、片单与电影人资料。

“中国版”指服务中文用户，同时收录华语和全球作品。要有中文译名、地区别名、原片名与演职员译名检索，不把片库限制为国产电影。

## IMDb 与豆瓣的差别

两者都有电影条目、评分、影评、片单和搜索，并不是功能互斥。主要差别在于重心与信息组织方式。

| 方面 | IMDb | 豆瓣 |
| --- | --- | --- |
| 产品重心 | 影视资料数据库，同时包含消费端发现内容和行业服务 | 围绕电影、书、音乐等内容形成的中文文化社区 |
| 资料关联 | 作品、演职员、角色、参与作品等关联突出 | 中文电影资料、观影记录、用户评价、标签与讨论突出 |
| 评分 | 十分制用户评分 | 五星制用户评分，通常以十分制展示聚合分数 |
| 社区体验 | 用户影评、片单、投票等 | 短评、长评、好友动态、片单、小组等社区体验 |
| 行业服务 | IMDbPro 等面向行业人士的服务 | 消费者文化内容与社区更突出 |

豆瓣已经覆盖不少“中文 IMDb”的需求。项目不能只靠中文界面形成差异；应验证用户是否会因为标签更贴切、组合更灵活、资料更可靠而持续使用。

## 本次 IMDb 页面观察

直接查看了 [IMDb 首页](https://www.imdb.com/) 与导航菜单。首页可见预告片与采访、专题推荐、人物趋势、用户评分、Watchlist、观看选项与电视剧集入口。菜单按 Movies、Celebs、TV shows、Watch、Awards & events、Community 分组。

电影目录中可见上映日历、Top 250、热门影片、按类型浏览、票房、场次与票务、新闻。人物、奖项、社区也各有入口。此次没有登录、提交评价或操作账户。

## 整个平台的信息结构

- 发现：编辑片单、不同观影感受的入口、已核验的热门内容。
- 电影库：类型、情绪气质、主题、节奏、叙事、年代、地区、语言、片长组合筛选。
- 影片页：中文名与别名、原名、海报、简介、演职员、标签、关联作品、用户评分与评论、资料来源。
- 电影人：姓名与译名、职业、参与作品、角色、合作关系。
- 榜单：满足最低评价样本要求后形成的口碑榜；热度榜与评分榜分别解释计算方式。
- 我的：想看、看过、个人评分、个人片单、观影记录。
- 资料贡献：用户提交缺失影片和纠错，由审核流程合并到正式条目。

网站适合作为可检索、可分享的资料中心；小程序可以承载选片、想看与个人记录。共用同一套服务与数据模型，第一版界面先验证选片体验。

## 当前 UI 与后续服务

当前前端使用有限示例数据，提供真实海报、自由筛选、搜索、电影详情、导演关联搜索、主题片单、个人评分与本机想看记录。个人记录保存在当前浏览器；没有宣称已经建立公共评分或跨设备账户。

全球资料导入、社区评价、演员完整职业资料、排行榜、新闻、预告片托管与播放渠道核验需要后续服务，当前界面不会虚构这些数据。

优先补齐两条完整链路：

1. 搜索或组合标签找到电影，进入资料，沿导演与标签继续探索，加入想看，观影后记录评分。
2. 编辑或贡献者补齐影片资料，保留来源，经审核发布，用户能纠错。

## 全球片库的数据基础

影片、人物、演职关系、译名别名、图片、标签、用户记录、评分应独立建模。使用内部稳定 ID，通过外部来源 ID 映射去重，不以片名字符串作为唯一标识。

先导入基础资料，再逐批完善主观标签。未标注代表未知，不能当作“不具备该内容”。缺失海报允许占位并可补录；不同发行版本、片长与地区资料保留来源。

大规模片库应在服务端分页、检索、计算分面数量，用搜索索引加速组合条件。海报使用缩略图与缓存，前端每次只取当前页，不一次下载全球片库。

电影资料源的覆盖、更新频率与使用条件要分别评估。IMDb 作为功能参考不等于能够直接把它的全部内容复制为自有商业数据库。正式接入前确定可持续使用的数据源，并保留每个字段与图片的出处。

## 建议先验证的特色

“爱情、喜剧”只是起点，用户还可以表达“成年人关系、轻松、有现实感、不苦情”。需要为这些主观标签提供定义和真实例子，并区分整体气质与局部情节。

第一阶段验证这些细需求是否经常出现、能否被稳定标注、组合后是否有足够结果，以及用户是否真的选中并看了电影。之后再扩大资料规模和社区功能。
